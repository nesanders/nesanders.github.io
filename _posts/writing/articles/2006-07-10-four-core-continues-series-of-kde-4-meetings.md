*This article was originally published on Newsforge on 2006-07-10 at https://trends.newsforge.com/trends/06/07/10/2047210.shtml, but is no longer available elsewhere online.*

In another of several events designed to accelerate the development of the <a href="https://kde.org/">K Desktop Environment's</a> next major release, members of the KDE project attended the <a href="https://dot.kde.org/1151271635/">Four Core meeting</a> last week (July first through the seventh).  Attendees were committed to readying the fundamental kdelibs and kdebase packages for version four so that work on overlying applications may continue.  Attendee <a href="https://aseigo.blogspot.com/2006/07/trysil.html">Aaron Seigo comments</a>, "I get the feeling more than ever that KDE 4 really takes off here."

All the KDE 4 meetings, such as the recent <a href="https://software.newsforge.com/software/06/05/31/1536229.shtml">Multimedia Meeting</a>, are intended to build team coherence and direction as much as to write code.  All attendees seemed to feel that the meeting was successful in removing the hurdles that so often face a development team working together from places scattered throughout every corner of the world.

Fair weather in Trysil, Norway throughout the week aided both spirits and efforts.  <a href="https://aseigo.blogspot.com/2006/07/trysil-sunday.html">Seigo writes</a>, "One of the goals for KDE 4's interface is to be more organic, which is to say to behave more like the real world which we are well adapted to.  In keeping with that we went for a walk out to a meadow for one of our two group meetings today."  Work was done in a rustic Norwegian lodge selected to minimize distraction.  To that end, attendees enjoyed <a href="https://aseigo.blogspot.com/2006/07/trysil-thursday.html">beautiful</a> <a href="https://chaos.troll.no/~harald/kdefour/">scenery</a> and catered food.  Nonetheless, <a href="https://ervin.ipsquad.net/index.php/2006/07/04/51-kde-four-core-day-3-4">World Cup fever</a> prevailed midweek.

On Wednesday, a reporter for the Hamar Arbeiderblad, a local newspaper, <a href="https://blogs.qtdeveloper.net/archives/2006/07/09/kde-four-meeting/">visited the hackers</a>.  The paper was apparently responding to an alert made by a local KDE user, who also visited the group.  The resulting article, <a href="https://www.h-a.no/artikkel.asp?Artid=226072">"Building the Future of Computing in Trysil"</a>, can be viewed by paid users of the h-a website.

Hacking done at the meeting revolved around outfitting KDE's low-level libraries for use in a new and modern desktop.  Tasks involved in such a transition include implementing the cross-desktop standard communication tool <a href="https://dbus.freedesktop.org/doc/dbus-faq.html">DBUS</a> to replace KDE 3's DCOP, porting Qt calls to use the new <a href="https://www.trolltech.com/company/newsroom/announcements/press.2006-06-26.0683224314">version 4.2</a>, and, of course, bugfixing.  It was also decided to remove <a href="https://aseigo.blogspot.com/2006/07/and-then-they-got-familiar.html">a few dozen obsolete classes</a> from within the code of kdelibs.   With the libraries more or less functional, the team must decide how to evolve them to suit the needs of KDE 4.  <a href="https://aseigo.blogspot.com/2006/07/trysil-tuesday.html">Seigo writes</a>, "We had a couple of quite long meetings today about kdelibs: what should go into kdelibs; how should we handle the process of managing the public APIs; what are our goals and practices for binary compatibility ... not trivial topics even if the questions are easily stated."

Though the meeting focused on the fundamentals, the team could not resist working on and discussing some higher-level code.  <a href="https://usability.kde.org/hig/">KDE's Human Interface Guidelines</a> and accessability tools were topics of great discussion.  <a href="https://en.wikipedia.org/wiki/KIO">KIO</a> continues to be worked on, particularly its seeking feature first written during the KDE Four Multimedia meeting.  A redesign of the KJob class should also benefit KIO, which uses it extensively, as well as emerging technologies such as Akonadi and <a href="https://solid.kde.org/">Solid</a>.  <a href="https://pim.kde.org/akonadi/">Akonadi</a> is a forthcoming Personal Information Management storage solution first proposed during <a href="https://pim.kde.org/development/meetings/osnabrueck4/overview.php">January's KDE PIM meeting</a>.  

Whenever discussing a new major version, replacing old technologies must be addressed.  To aid the switch to DBUS, a graphical browser was planned which will work much the same way KDCOP does today, allowing users to easily see all the information and settings applications offer to each other.  LiveUI looks to replace the GUI development tool <a href="https://developer.kde.org/documentation/library/kdeqt/kde3arch/xmlgui.html">XML GUI</a>.  A new composition manager is to be built into the KWin window manager to replace the independent <a href="https://docs.kde.org/stable/en/kdebase/kompmgr/index.html">kompmgr</a>.  As attendee <a href="https://ervin.ipsquad.net/index.php/2006/07/06/53-kde-four-core-day-6">Par Ervin commented</a>, "We've still so much to do, but the improvements made in the last few days are really motivating."  On that thought, <a href="https://blogs.qtdeveloper.net/archives/2006/07/07/kde-four-core-meeting-in-trysil/">Simon Hausmann warns</a>, "stay tuned for upcoming announcements of other things that happened here..."
